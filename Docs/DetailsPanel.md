# ImGui Details panel

The initial Details port replaces the property tree in the four Level Editor
Details tabs. It uses the existing **Enable ImGui UI** setting and requires the
same editor restart as the other ports. No additional preference is introduced.
Asset-editor inspectors, property pickers, UMG, and runtime widgets keep their
existing presentations.

## Implementation

`PropertyEditor` exposes an optional tree-content factory. `SDetailsView` retains
the native property model, selection, custom layouts, filtering, sections, and
commands. Its native tree remains an unattached backend for expansion state and
on-demand fallback rows. It is not mounted behind the ImGui view.

`SImGuiDetailsView` draws categories, nested properties, advanced expansion, and
resizable property/value columns. Categories use full-width ImGui collapsing
headers with the current theme's header colors, retaining native expansion state
and context actions. `FTBImGuiPropertyEditor` is the reusable value
editor for standard booleans, enums, integer/floating-point numbers, strings, and
names. Numbers currently use committed text fields rather than live sliders.
Enter or leaving an edited field commits; Escape cancels.

Writes run after the ImGui frame through `IPropertyHandle` with its default
transaction flags. Native property notifications, package changes, multi-object
editing, reset handlers, enum restrictions, edit conditions, and read-only policy
are retained. Failed value imports produce an error indicator with a tooltip.
Queued operations verify that their row still belongs to the current tree before
executing. Fallback popovers close when their row leaves the current tree.

CallInEditor functions generated by Unreal's function-call helpers appear as direct
ImGui buttons. They use the same execution and permission delegates as the native
buttons, including execution context, script guards, and transactions. Calls run
after the ImGui frame and recheck that their row is still current. The buttons keep
their native labels/tooltips rather than displaying the accumulated search text.

The actor/component tree, name area, search field, section controls, and view
options are still native. The port does not alter shared Slate widget classes or
install a global style replacement. Each Details instance currently uses the
existing self-contained ImGui host; sharing contexts across panels remains future
foundation work.

## Remaining custom editors

Mesh and material references now have direct ImGui asset controls: a native
thumbnail, asset-name picker button, use-selection, browse, clear where permitted,
reset and thumbnail double-click to open. Single-asset Content Browser drops use
the native asset editor's class, tag and reference filtering. Assignments, resets
and button actions are queued after the frame and verify that their row is current.
The picker popup uses Unreal's asset selector, not the full fallback property row.
Static Mesh component customization and material-slot replacement callbacks expose
the same presentation data; standard static/skeletal mesh and material properties
can also use it. Specialized customizations without this adapter keep their fallback.
Material-slot extension controls (used textures, Nanite override browsing and
plugin-added buttons) remain available from the native row context action.

Rows with custom widgets or type customizations, including transform controls,
other asset/object pickers, colors, localized text, and collection headers, open their
native row through **Edit...**. Children exposed by the native layout remain
available in the ImGui hierarchy. Property-specific buttons, keyframing, favorites,
and specialized row context actions remain on the native fallback row. The row
name's right-click menu also exposes the native editor and standard value
copy/paste for supported values.

Property highlighting/scroll requests and property-specific drag/drop are not yet
bridged to the ImGui tree. Numeric fields do not yet provide native unit parsing,
expressions, or interactive scrubbing.

This is a property-tree foundation, not complete Details visual parity. Native
customizations can still construct Slate widgets while generating their layouts.
No performance improvement is claimed until measured in the editor.

## Native Details comparison (22 October 2026)

Project Settings, including Houdini Engine settings, still uses the native Slate
tree. The factory in `TBImGuiDetailsIntegration.cpp` only accepts the four Level
Editor Details identifiers. A Project Settings row-generation ensure is therefore
not evidence that ImGui is drawing that panel.

| Area | Current ImGui behavior | Remaining work |
| --- | --- | --- |
| Property model | Uses native layouts, filtering, handles, multi-object values and transactions | Exercise plugin-specific refresh and invalidation paths in the editor |
| Standard values | Direct bool, enum, numeric text, string and name editors | Numeric scrubbing, sliders, units, expressions, multiline/password fields and bitmasks |
| Custom editors | Mesh/material references use inline asset controls; other custom rows open a native Edit... popover | Direct transforms, colors, remaining object/class references, localized text and plugin controls |
| Collections | Native children remain in the hierarchy; header uses native fallback | Inline add/remove/duplicate/clear, map keys and array reordering |
| Row actions | Reset, basic value clipboard and native fallback; CallInEditor callbacks are direct buttons | Native custom clipboard delegates, extension buttons, keyframing, favorites and full context menus |
| Reset policy | Custom overrides take precedence; NoResetToDefault metadata is respected | Render custom reset widgets directly instead of native fallback |
| Navigation | Expansion follows native state, including recursive expansion | Native scroll/highlight requests, complete keyboard navigation and property drag/drop |
| Panel chrome | Actor/component tree, search, sections, locking and options remain native | Port these independently after row behavior is complete |
| Cost | Offscreen values are skipped, but expanded rows are still traversed | Flatten/cache visible rows and clip traversal; measure layout, input and rendering costs |
| Customization construction | Existing customizations can construct Slate widgets while generating layouts | Separate action/value metadata from widget construction for common customization families |

The next foundation work should be row-action and metadata parity, followed by
transforms, references, colors and collections. Converting arbitrary Slate widgets
automatically is not implemented. Expanding the factory to Project Settings before
these adapters exist would replace rich controls with more fallback popovers.

The reset-override recovery preserves the existing custom-widget precedence when
both the property row and widget define an override. It logs the property path
once per row rather than breaking into the debugger. The widget override is
snapshotted before writing the destination, which may alias the custom widget.
This does not identify which customization installed overlapping overrides in the
reported Houdini session; the warning provides the property path for that check.

## Validation

Source/API and formatting checks only; no build or editor launch was performed.
Runtime checks still required:

- Select actors and components in each Details tab; lock a tab and change selection.
- Edit booleans, numbers, names, strings, and enums; undo/redo and verify dirty state.
- Multi-select objects with differing values and edit one shared property.
- Exercise edit-condition toggles, read-only properties, min/max limits, and reset overrides.
- Search, select sections, show modified/advanced properties, and expand/collapse recursively.
- Open transform, asset, color, collection, and plugin-specific fallback editors.
- Change selection, undo, delete an actor, or recompile a Blueprint while a fallback editor is open.
- Confirm native rendering after restarting with the global ImGui UI setting disabled.
